# P2.6: Harden

**Outcome:** the loop works on a repo with an install step, `status` says whether a turn is working or
stuck, and a goal whose proofs cannot run is caught before a turn is spent. Still CLI. Comes from the
expenses-backend probe ([`later/portability.md`](../later/portability.md), friction #26 to #31).

**Depends on:** P2.5 merged. Runs before [P3](P3-app.md): the app's live view reads what `status` derives, and
the plan's gate says to fix the loop before widening it.

## Scope

In:
- `setup_command`, run in the worktree before the first turn (friction #27, #11, #20).
- A `status` that answers "working or stuck" from the event log (friction #26).
- `status` and `log` take a thread id, like `review`, `accept`, `ship` and `discard` already do.
- Goal-side checks at `goal approve` (friction #30, #31).
- Re-run the Elixir probe afterwards and answer the question it left open: does the output match
  expenses-backend#323?

Out: allowlist ergonomics (friction #28, #29: an `env` form in `[tools]`, a decision for deleting inside the
worktree). They need a design choice and are better judged on the re-run. Gitignored files (#2) and git
hooks (#3) wait for a probe that hits them. A thread list that mixes active and finished threads, a queue,
anything concurrent.

## Design

### `status` is derived, never stored

Everything below comes from the event log by the same pure function that already derives the thread's state.
No new file, no second copy.

```
thread g-2026-10-14-crm-contract   running   turn 1 of 1
  elapsed      4m12s of 30m
  last event   tool_use Edit examples.json   (6 s ago)
  tool calls   41   denied 3
  cost so far  $0.00 (open turn's cost comes with its result)
```

"Quiet for N s" is shown when the last event is older than a threshold, so stuck reads differently from
slow. The open turn's cost is not known: `claude` reports it only in the result line, so "cost so far" is the
completed turns.

### One thread, still

`status [id]` and `log [id]` read any thread on disk; they do not make a second one active. `status --all`
(one line per thread: id, state, how it ended, cost) is a read-only view over `.workbench/threads/`. It is
the "short history" P3 already lists, not a thread list in the sense of the scope rule: nothing in it can be
started, run or queued from there.

### `setup_command`

A config key, validated like `check_command` (`Config` validation, no shell interpolation of thread text).
Runs once in the new worktree before the first turn, through `GitRunner`'s bounded runner with its own
timeout and capped output. Its result is an event; a failure ends the thread's start with the output shown,
before any turn is spent. It is not run again on send-back.

## Tasks

0. **Tidy `Thread/`, a move and nothing else** (done). First commit of task 1's PR, so the diff of the logic that
   follows is readable. Move the plan and result value types out of `ThreadService.swift`
   (`DiscardPlan`, `AcceptPlan`, `AcceptResult`, `Confirmation` and their `render()`, about 110 lines) into
   `ThreadPlans.swift`, and group the flat directory into `Thread/Ship/`, `Thread/Check/` and
   `Thread/Review/`. No behaviour change, no edited lines inside the moved code. `ThreadRunner` stays one
   file: it is one actor whose job is that a turn always ends, and splitting its private state would scatter
   that guarantee. `scripts/check.sh` unchanged and green is the proof.
1. **`status` from the log** (done: `Progress` in `Thread/ThreadState.swift`). Elapsed vs timeout, last event and
   its age, tool and denied counts, quiet-for. Cost so far is completed turns only: `claude` puts cost in the
   result line, so the open turn's is unknown until it ends. `--json` carries the same fields (exit codes unchanged).
2. **Thread id on `status` and `log`** (both already took one), and `status --all` (done).
3. **`setup_command`** (done: `Thread/Check/SetupRunner.swift`). Config key, bounded run in the worktree, event, refuse to start the turn on failure.
   Fresh-worktree test with a setup that fails and one that succeeds.
4. **Goal checks at approve.** Warn when a proof names a command the allowlist denies; accept continuation
   lines in out-of-scope bullets (or say it in the spec).
5. **Re-run the Elixir probe** on the same task with `setup_command` set. Record the result in
   `later/portability.md`; fix nothing during it.

Tasks 0, 1 and 2 are one PR (both change what `status` reads). Task 3 is its own, the largest and the one that
matters most. Docs travel with each: `docs/spec/` for the event and the config key.
